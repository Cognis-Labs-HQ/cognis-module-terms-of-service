# モジュールを開発者テンプレートに統一

**機能ブランチ:** feature-align-module-template

## フロー境界で同意レポートを認可

ctx の直接呼び出しも含め、同意レポートフローには検証済み管理者リクエストが必要です。HTTP ハンドラーは同じ認可ステージへリクエストコンテキストを渡し、その後にアカウントの同意レコードを読みます。

## 同意確認の翻訳エラーを伝播

プロバイダーのマウントは初回確認を待機し、英語のフォールバックキーがなければ失敗します。失敗したプロバイダーは所有するフッターリンクとリスナーを解放し、定期確認の翻訳エラーも伝播させてポーリングを停止します。

## 法的文書の変更をフロー内で監査

公開と同意記録の成功時に、実行フローから検証済み操作主体と対象文書またはアカウントを含む info 監査ログを一度記録します。HTTP ルートによる重複記録を削除しました。

## 中断時に読み込み状態を解放

1.5.47 — 直接ページを中断すると、翻訳、プロバイダー、コンポーザーの初期化が保留中でも共通の読み込みトークンを直ちに解放します。リソースのクリーンアップは同じホストシグナルに結び付けます。

## パッケージの参照先と開発者向けガイド

リリース 1.5.46 — パッケージ検証では、エントリーポイント、アイコン、バナー、スクリーンショットが、解決済みのパスを含めチェックアウト内の通常ファイルであることを確認します。ドキュメントは公開契約を説明し、リリースのメタデータにはマニフェストを参照します。変更履歴にはリリースの来歴を保持します。 公開の法的文書ページはホストの直接エントリーのライフサイクルシグナルを使用します。翻訳や文書の読み込みが中断された場合、古いUIを公開せず、コンポーザーを破棄します。遅延した初期化は移動先のフッターを更新しません。読み込みトークンは完了、失敗、中断のいずれでも解放します。

## 標準構成と所有範囲を守る統合

テンプレートの指針、ドメイン別ルート、翻訳された統合文書、実行可能な構成チェック、最終パッケージハッシュを同期します。公開URLとモジュール識別子は維持します。ブラウザーの提供機能は担当ホストのライフサイクル契約に従います。

## バナー全体を表示範囲に収める

Terms of Service バナーを再構成し、Marketplace の切り抜き後もロゴ、タイトル、文書、盾の全体を表示します。既存の文書アイコンは維持します。

## Marketplace の説明を統一する

Marketplace のメタデータに短い操作概要と具体的な機能説明を使用し、翻訳の意味を揃えます。

## マーケットプレイスの名前と法的文書エディターの幅を復元

公開済みのマーケットプレイス翻訳識別子をリリースチャネル間で維持します。ホストの UI 再利用機能を通じてモジュール所有の法的文書スタイルシートを読み込み、管理画面のテキストエディターが利用可能な幅全体を使用するようにします。

## 法的文書の変更を認可

公開と同意のフローは認可段階でリクエストを認証します。公開には管理者権限が必要で、更新者と同意アカウントの識別子は検証済みクレームだけから取得します。直接のフロー呼び出しと偽装された識別子をテストします。認証フッターの文書もディスクリプター提供者の契約に合わせて修正します。

## 法的文書セクションの読み込みを修正

モジュール所有の CSS は公開の page-styles ヘルパーで読み込みます。共有スタイルシートの一覧は再利用リソースの相対名だけを受け付けるため、モジュール URL を渡すと UI のインポートが失敗し、法的文書セクションが非表示になっていました。テストでこの境界と管理セクションの検出を確認します。

## 翻訳キーでモジュール ID を維持

翻訳キーには `module.<manifest.id>.<feature>.<label>` を使用します。複数の単語からなるモジュール ID はハイフンを含めてそのまま保持します。`terms-of-service` の場合は `module.terms-of-service.admin.title` を使用します。モジュール ID より後の接尾辞には、小文字の単語をピリオドで区切って使用します。マニフェストのメタデータ、XML ファイル、コード参照で同じ名前空間を使用します。

## フッターの法的文書リンクを維持

個別に読み込まれる静的スクリプトやバンドルを含め、すべてのブラウザークライアントは `ctx` 所有のフッター登録先を使用します。フッターのディスクリプターで `target: "_blank"` を指定すると、描画側が `noopener noreferrer` を追加します。認証提供者は翻訳済みラベルと認証コンテキストを提供し、ログイン済みの法的文書リンクは明示的にアプリケーションコンテキストへ登録します。履歴やブラウザーキャッシュからの復元時に公開済み文書へのリンクを更新し、コアのライセンスや変更履歴のリンクは置き換えません。

## フッター描画から独立して同意を適用

選択言語の翻訳キーがない場合は、ユーザーの言語設定を変更せずにモジュールの英語文字列を使用します。翻訳の欠落とフッター登録の失敗を安全な診断項目とともに記録します。フッターの失敗が必須同意、送信、拒否とログアウトを妨げることはありません。

## 文字列の直接指定を禁止し翻訳キーを必須にする

AI向け指示では、すべての経路で英語のユーザー向け文字列の直接指定を禁止します。選択言語に値がない場合は英語のXMLリソースの同じキーを使用できます。英語の代替値も未定義または空の場合は、英語の直接指定、キー名、空の文字列を表示せず、明示的に失敗させます。翻訳の欠落によるエラーを握りつぶしてはいけません。

## Core共通の翻訳リゾルバーを利用

公開の法的文書ページ、フッター登録、同意の適用処理は、モジュールのバンドルURLを渡してホストの`createI18n`を利用します。英語XMLへのフォールバックとキー欠落時の明示的な失敗はCoreが担当します。翻訳エラーは同意の適用処理にも伝播し、フッター描画のエラー分離で握りつぶされません。
