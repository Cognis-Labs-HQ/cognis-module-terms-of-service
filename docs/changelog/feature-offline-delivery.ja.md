# 送信待ちと同意

**機能ブランチ:** feature-offline-delivery

## 同意キャッシュの安全性

同意のスナップショットは、古い応答に含まれない既知の文書も保持します。新しく公開された未同意の文書は、現行版への同意がサーバーで確認されるまで、オフラインアクセスとキュー送信を阻止します。キャッシュ容量の上限や保存失敗時は、最新のオンライン状態を破棄せずにオフライン権限を取り消します。必須の同意画面、オンライン同意、公開の法的文書表示は引き続き動作します。アカウント単位で共有されるメモリ内状態により、キャッシュ失敗中も確認済みの版を保持し、同じページの別クライアントが古い保存済み権限を復元することを防ぎます。完全な同意済みスナップショットの保存に成功した場合のみ、オフライン権限が回復します。

## 送信待ちと同意

復旧ではプロバイダーを更新し、`authenticate-session` の最終段階 `afterSession` で送信します。必須プロバイダーはサーバーカタログに `offlineAccessGuard` を宣言します。要件が不明または未同意の場合はオフライン利用を拒否します。Terms of Service は最後に取得した文書の版とサーバー確認済みの同意をアカウント別に保存します。新しい未同意の版を取得すると、オフラインの読み取り・移動・書き込みを直ちに禁止し、オンラインで同意するまで送信も停止します。オフラインでは同意できません。非公開コンテンツはタブ内のみで、再読み込み後も残るのは容量制限付きのキューと法的文書です。

ホストは ctx 経由で `offline:outbox`、`offline:state`、`offline:accessPolicy` を提供します。各コンポーネントはプロバイダーの有効期間中に送信処理を登録し、安定した操作 ID を `offline:enqueue` に渡します。`offline:flush` が認可と送信を行います。永続キューはアカウント別で最大 1,000 件・1 MB・7 日間、トークンは保存しません。元の ID と時刻を維持し、一時的な失敗を再試行し、確認済みまたは恒久的に拒否された項目を削除します。拒否は翻訳済みの警告で通知します。ログアウトで当該アカウントのキューを消去し、他のアカウントのデータは送信しません。オフラインモードを無効にすると新規保存を停止します。既存の項目はオンラインで送信できます。

## オフラインの定期確認の制限

オフラインモードでは、同意確認と通常の接続復旧の定期確認を停止します。ブラウザーのオンラインイベントが繰り返されても、軽量のサーバーヘルスチェックだけを十五分ごとに実行します。オンラインでの接続確認の失敗時は最大十五分まで間隔を延ばします。同意確認は失敗時に最大五分まで間隔を延ばし、オフラインでは完全に停止して再接続後に再開します。必要な文書へのキャッシュ済みの同意は引き続きオフラインアクセスの条件です。
