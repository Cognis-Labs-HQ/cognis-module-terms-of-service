# 登録時の同意の制限

**機能ブランチ:** feature-onboarding-consent-scope

## 登録時の同意の制限

登録はバージョン1のauth:onboarding契約を使用します。constructRegistrationUiへの登録ではterms-of-service:consent:statusとterms-of-service:consent:recordのみを宣言します。完了コールバックはexecuteOnboardingを受け取り、同意チェックボックスが明示的に選択されていなければ処理を拒否します。現在公開されている文書の正確なバージョンを送信します。同意の欠落、不正または不完全なバージョンは拒否され、変更済みまたは同意済みのバージョンは競合となり、自動的に再同意しません。

Authは検証済みの登録アカウントを提供し、有効期限、失効、操作の可用性、提供元の有効期間を管理します。モジュールは登録入力からアカウントIDを受け取りません。準備フローは検証のみを行い、直接呼び出しても同意を保存できません。初期化後と、非同期の文書読み取りに続く保存の直前に権限を再確認します。通常の同意、報告、公開ルートは既存のセッションと役割の検証を維持します。

まずauth:onboardingと制限付き登録コールバック契約を備えたCognisホストを導入し、登録を再開する前にこのモジュールを更新してください。ホストとモジュールは連携してリリースします。認証済みapiFetchを前提とする古いコールバックは、制限付き登録資格情報では動作しません。auth:onboardingがなければモジュールの起動を拒否します。広い権限のトークンへの切り替えや旧フローの別名はありません。既存の文書と同意済みバージョンは保持されます。

同意の保存とAuth資格情報の失効は別々の操作です。実行中のデータベース書き込みは後からのキャンセルでは取り消せず、保存成功後に応答や失効確認が失敗する場合があります。通常のログインで現在の同意状態を確認し、通信失敗から同意済みと判断しないでください。登録はユーザーが明示的に選択した場合のみ同意を送信します。
