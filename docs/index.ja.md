# 利用規約モジュール標準

この文書は Cognis 利用規約外部モジュールがサポートするアーキテクチャを定義します。

## 公開コントラクト

モジュールは公開 SPA ルート `/terms-of-service`、`/privacy-policy`、`/eula` を登録します。Browser エントリーポイントはこれらの公開パスでのみ直接 Mount され、管理画面には `registerAdminSection` を通じてローカライズされた法務セクションを1つ追加します。認証 API ルートには必要最小限のロールを要求します。管理画面と同意画面が Host の内部ユーザーディレクトリ、アカウントライフサイクル Endpoint、および保護されたチェックボックス Style Contract を使用するため、Manifest は本モジュールを特権モジュールとして指定します。

公開された法的コンテンツは Cognis が `ui:reuse` を介して描画する Markdown です。保存するたびに `docs:versionStore` を介して不変バージョンを追記します。モジュールは Cognis 内部実装や特定のデータベースドライバーをインポートしません。

法的文書エディターは、ホストの折りたたみセクション Composer を使用して文書ディスクリプターを全幅の1グループとして表示し、セクションを描画できるようローカライズされた開閉ラベルを渡します。ローカライズされたタイトルはプレーンテキストとし、サニタイズ済みの追加/削除、作成/プレビュー操作とエディター内容には Composer の信頼済み HTML フィールドを使用します。現在マウントされているエディターによって追加または削除の状態を決定します。削除を確定すると、不変の公開済みバージョンを削除せずにエディターを閉じ、操作を追加に戻します。作成とプレビューには、全幅でサイズ変更不可のエディター下部にあるホストの中立操作行ボタンを使用し、モジュールは Cognis の情報ツールチップとフローティング変更追跡ユーティリティを使用します。エディターを追加すると、余白を備えたサイズ変更不可の Markdown 入力欄と、Messages Composer 形式の作成・プレビューボタンが表示されます。変更追跡の保存操作は固定文書ごとの正確な API ルートを通じて更新を公開し、Host のトーストで成功を通知します。公開済みエディターはページ更新後に保存済み Markdown とともに再表示されます。破棄すると公開済み内容を復元し、未保存の新規エディターの場合は閉じて操作を追加に戻します。エディターの削除には確認が必要です。

## 同意とライフサイクル

各アカウントが同意した利用条件とプライバシーの正確なバージョンを記録します。登録では明示的な同意が必須です。認証セッション Flow と5秒ごとのフォアグラウンド更新確認により、記録済みバージョンが最新でないアカウントを速やかにブロックし、同意時に公開済みの全バージョンを一括記録し、拒否時にログアウトします。強制中も公開法務ページは閲覧できます。同意ダイアログは必須かつ単一で、開く前にモジュールスタイルとコアのチェックボックスおよび Pill スタイルを明示的に読み込み、更新時と SPA ナビゲーション時の表示を統一し、認証済みアカウントライフサイクルの削除操作と、明確に「キャンセル」と表示された選択肢を提供し、拒否時はホストのログアウト Flow を実行します。認証済み同意統合は、ログイン済み Shell 内の冪等な右寄せ Footer リンクを管理します。認証フッターは `ctx.registerAuthFooterPlugin({ scriptUrl })` を通じてディスクリプター提供者を登録します。`listAuthFooterLinks()` は匿名公開インデックスを読み込み、公開済み文書のローカライズされたリンクディスクリプターだけを返します。描画、コアリンクの表示状態、モジュール無効化時の提供情報の削除はホストが管理します。すべての法的ページは Cognis ページ Composer を使用します。認証済みアカウントには完全な Shell を提供します。ログインセッションのない訪問者には Composer の文書フレーム、ページコンテキスト、セクションツールバーを維持しながら、アカウント依存のトップバー、ナビゲーション、テーマ切り替え、Footer、レイアウト保存、アカウント拡張を非表示にします。これらのページは自然な文書スクロールを使用し、Core の再利用 Export `side-menu.js` を介して、描画された見出しからグループ化された折りたたみ可能なセクションナビゲーションを構築します。各項目は見出しを `targetId` として渡すため、Core の Side Menu Controller が先頭位置に揃えるスムーズスクロールを担当し、モジュールは選択状態を更新します。見出しの Scroll Margin により、選択した見出しが固定 Shell Header の下に隠れません。同意統合が引き続き `ui:footerLinks` の唯一の所有者となります。法務ルート上でも公開状態を読み込み、公開済み文書だけを提供し、SPA のページ Mount が切り替わってもリンクを維持し、ルート遷移ごとに再調整し、法務ページの Mount 後に Registry 通知を発生させて再利用された Shell の Footer を再描画して、Core Footer が該当ルートを Active として示せるようにします。各法務ルートは認証済み Shell の準備後にローカライズされた文書タイトルを適用するため、完全更新時も SPA ナビゲーション時も正しいページコンテキストが表示されます。同意状態は公開済みの利用条件、プライバシー、EULA の各バージョンごとに個別に評価され、永続ポップアップには未承認文書だけがチェックボックスカードとして表示され、公開済みの完全なバージョンセットが送信されます。必須チェックボックスをすべて選択するまで送信ボタンは無効です。API は不正または不完全な公開済みバージョンセットを HTTP 400 で拒否し、クライアントは Host の Toast Capability でローカライズされたエラーを表示します。再訪ユーザーには、Popup のリンクが通常の全画面法務 Route を `?view=changes` 付きで開きます。この認証済み View は `docs:versionStore` を通じて同意済み Hash と最新 Hash を比較し、構造化された結果を `ui:documentDiff` で描画するため、同意前に追加、削除、変更された行を確認できます。通常の Footer リンクは引き続き現在の文書を開きます。移行前の履歴バージョンが存在しない場合、API は明示的な利用不可結果を返し、ページは比較を黙って隠さずローカライズされた説明を表示します。 管理画面では公開済み文書にのみ検索可能な同意表を表示し、常に1つだけが押下状態として明確に表示される、すべて、承認済み、未承認のフィルターと、ホストの `ui:pagination` 機能が提供する10行単位のページングを備えます。緑と赤のステータス Pill で承認済みと未承認のアカウントを区別し、同意済みバージョン列と最新バージョン列に、各アカウントが同意したバージョンと現在公開中のハッシュを並べて表示します。同意記録がないアカウントにはローカライズされた値を表示し、内部の未公開 Sentinel を同意済みバージョンとして公開しません。法務文書の読み込みは付随するユーザーおよび同意レポート要求とは独立して完了するため、レポートの失敗によって公開済みエディターが空として表示されることはありません。更新を公開すると、返されたバージョンに対して表示中の全アカウントの状態を直ちに再計算し、レポートを再描画します。同意が成功すると直ちに Browser Event を発生させ、表示中の管理レポートも5秒ごとに API から更新するため、別セッションで記録された同意もページを再読み込みせずに表示されます。作成とプレビューには対応する押下状態と、選択中のボタンが分かる表示を設定します。公開済み文書ごとの同意は独立しており、未公開文書の列には明示的な非 Null 値を使用します。公開法務ルートでは同意ポップアップを表示せず、Page Composer より先に読み込み状態と認証セッションを初期化し、バージョンストアの Markdown フィールドを描画します。また、内容に合わせたサイズの Composer 要素を使用し、ログイン済みユーザーに適切な大きさの完全な Cognis Shell を提供します。

スコープ付き登録はモジュール無効化時に削除されます。読み込み済みの Browser Hook が更新または再起動中にモジュールの同意 Endpoint が一時的に利用不能であることを検出した場合、Endpoint を記録し、Navigation を妨げず、定期的な再試行を続けて復旧後に同意の強制を再開します。Back-Forward Cache への Page Hide では有効な Listener と Timer を保持します。文書と同意は無効化や再起動後も保持され、アンインストール時は `deleteContent` が真の場合のみ削除されます。ブラウザーリソースは `cognis.uiCtx` と Host のフィードバック、ナビゲーション、API、Popup、i18n、ページエントリの各コントラクトを使用します。

## リポジトリ品質

ルートの Manifest、Package、Lockfile、Route メタデータは常に同期します。Server コードは `api/`、Browser コードは `ui/`、運用コマンドは `cli/`、ローカライズ文書は `docs/`、リリースメタデータは `docs/changelog/`、アートワークは `assets/` に配置します。テストはローカル Capability Fake を使用し、Route、永続化、Flow、ライフサイクル、ローカライズ、Package を検証します。

### 所有するアクションフロー

HTTP操作は、検証・実行・表示のステージを持つモジュール所有のctxフローを通じて実行します。テストはこれらのステージを実行し、検証やスキーマ初期化が失敗した場合に保存が行われないことを確認します。

### 開発者向け構成とホストの責任範囲

新しいモジュールは[cognis-module-template](https://github.com/Cognis-Labs-HQ/cognis-module-template)から作成し、このリポジトリでは`AGENTS.md`に記載されたテンプレート版の指針に従います。`bootstrap.js`はライフサイクルの調整、`api/index.js`はctx依存関係の接続、`api/routes/<domain>/index.js`はHTTP処理、`api/reuse/`は再利用するサーバーコードを担当します。ブラウザー機能は`ui/`、スタイルは`ui/styles/`、再利用するマークアップは`ui/templates/`、翻訳された文書は`docs/index.<locale>.md`に配置します。過去のリリース記録は`docs/changelog/`に置き、パッケージのハッシュ対象から除外します。対応しない任意の領域は作成しません。

公開ctx機能と宣言されたフローを利用し、Cognis内部や他のモジュールをインポートしないでください。ダッシュボードの機能・ナビゲーション提供スクリプトは`mountProvider(scopedUiCtx)`を公開し、所有するリソースの終了処理を返します。インポート時にモジュールの動作を登録してはいけません。ホストは無効化時に機能、フローフック、リスナー、提供状態を解除し、再有効化時にキャッシュ済みスクリプトを再マウントします。設定・管理画面のファクトリーと認証フッターの記述子は、それぞれの公開ホスト契約に従います。独立したテスト用実装で契約を検証し、構成チェックを実行し、最後のパッケージ変更後にハッシュを更新して、公開前にlint、テスト、マニフェスト検証を実行してください。

バナーの Cognis ロゴ、タイトル、文書画像全体を中央の安全領域に収め、Marketplace の高さ制限による切り抜きに対応します。既存の文書アイコンは維持します。

パッケージ検証では、エントリーポイント、アイコン、バナー、スクリーンショットが、解決済みのパスを含めチェックアウト内の通常ファイルであることを確認します。ドキュメントは公開契約を説明し、リリースのメタデータにはマニフェストを参照します。変更履歴にはリリースの来歴を保持します。 公開の法的文書ページはホストの直接エントリーのライフサイクルシグナルを使用します。翻訳や文書の読み込みが中断された場合、古いUIを公開せず、コンポーザーを破棄します。遅延した初期化は移動先のフッターを更新しません。読み込みトークンは完了、失敗、中断のいずれでも解放します。

直接ページを中断すると、翻訳、プロバイダー、コンポーザーの初期化が保留中でも共通の読み込みトークンを直ちに解放します。リソースのクリーンアップは同じホストシグナルに結び付けます。

公開、同意レポート、同意記録の各フローは、認可ステージ内で `auth:requireAuth` を使ってリクエストを認証します。公開と全アカウントの同意レポートには管理者権限が必要で、操作主体と同意アカウントの識別情報は検証済みクレームだけから取得します。`terms-of-service:listConsentForDocument` は `[request, response, slug]` で呼び出します。slug のみの指定や管理者以外のリクエストは、同意レコードを読む前に拒否されます。公開と同意記録が成功すると、実行フロー内で検証済みアカウントと対象文書を含む `info` 監査ログを一度記録します。ctx の直接呼び出しと HTTP リクエストの監査範囲は同じです。テストでは直接呼び出し、偽装された識別情報、レポートへのアクセス拒否、保存失敗を検証します。

モジュール所有の CSS は公開の page-styles ヘルパーで読み込みます。共有スタイルシートの一覧は再利用リソースの相対名だけを受け付けるため、モジュール URL を渡すと UI のインポートが失敗し、法的文書セクションが非表示になっていました。テストでこの境界と管理セクションの検出を確認します。

### 翻訳キーでモジュール ID を維持

翻訳キーには `module.<manifest.id>.<feature>.<label>` を使用します。複数の単語からなるモジュール ID はハイフンを含めてそのまま保持します。`terms-of-service` の場合は `module.terms-of-service.admin.title` を使用します。モジュール ID より後の接尾辞には、小文字の単語をピリオドで区切って使用します。マニフェストのメタデータ、XML ファイル、コード参照で同じ名前空間を使用します。

### フッターの法的文書リンクを維持

個別に読み込まれる静的スクリプトやバンドルを含め、すべてのブラウザークライアントは `ctx` 所有のフッター登録先を使用します。フッターのディスクリプターで `target: "_blank"` を指定すると、描画側が `noopener noreferrer` を追加します。認証提供者は翻訳済みラベルと認証コンテキストを提供し、ログイン済みの法的文書リンクは明示的にアプリケーションコンテキストへ登録します。履歴やブラウザーキャッシュからの復元時に公開済み文書へのリンクを更新し、コアのライセンスや変更履歴のリンクは置き換えません。

公開の法的文書ページ、フッター登録、同意の適用処理は、モジュールのバンドルURLを渡してホストの`createI18n`を利用します。英語XMLへのフォールバックとキー欠落時の明示的な失敗はCoreが担当します。翻訳エラーは同意の適用処理にも伝播し、フッター描画のエラー分離で握りつぶされません。

プロバイダーのマウントは初回の同意確認を待機します。英語のフォールバックキーが欠落または空の場合はマウントを失敗させ、所有するフッターリンクとナビゲーションリスナーを解放します。フォアグラウンド更新中の翻訳欠落も伝播させ、必須の同意を黙って省略せず、以後のポーリングを停止します。通常のフッター描画エラーは別途記録し、同意確認を妨げないようにします。

## 送信待ちと同意

復旧ではプロバイダーを更新し、`authenticate-session` の最終段階 `afterSession` で送信します。必須プロバイダーはサーバーカタログに `offlineAccessGuard` を宣言します。要件が不明または未同意の場合はオフライン利用を拒否します。Terms of Service は最後に取得した文書の版とサーバー確認済みの同意をアカウント別に保存します。新しい未同意の版を取得すると、オフラインの読み取り・移動・書き込みを直ちに禁止し、オンラインで同意するまで送信も停止します。オフラインでは同意できません。非公開コンテンツはタブ内のみで、再読み込み後も残るのは容量制限付きのキューと法的文書です。

ホストは ctx 経由で `offline:outbox`、`offline:state`、`offline:accessPolicy` を提供します。各コンポーネントはプロバイダーの有効期間中に送信処理を登録し、安定した操作 ID を `offline:enqueue` に渡します。`offline:flush` が認可と送信を行います。永続キューはアカウント別で最大 1,000 件・1 MB・7 日間、トークンは保存しません。元の ID と時刻を維持し、一時的な失敗を再試行し、確認済みまたは恒久的に拒否された項目を削除します。拒否は翻訳済みの警告で通知します。ログアウトで当該アカウントのキューを消去し、他のアカウントのデータは送信しません。オフラインモードを無効にすると新規保存を停止します。既存の項目はオンラインで送信できます。

## 同意キャッシュの安全性

同意のスナップショットは、古い応答に含まれない既知の文書も保持します。新しく公開された未同意の文書は、現行版への同意がサーバーで確認されるまで、オフラインアクセスとキュー送信を阻止します。キャッシュ容量の上限や保存失敗時は、最新のオンライン状態を破棄せずにオフライン権限を取り消します。必須の同意画面、オンライン同意、公開の法的文書表示は引き続き動作します。アカウント単位で共有されるメモリ内状態により、キャッシュ失敗中も確認済みの版を保持し、同じページの別クライアントが古い保存済み権限を復元することを防ぎます。完全な同意済みスナップショットの保存に成功した場合のみ、オフライン権限が回復します。
