# Terms of Service Module Standard

This document defines the supported architecture of the Cognis Terms of Service external module.

## Public Contract

The module registers the public `/terms-of-service`, `/privacy-policy`, and `/eula` SPA routes. Its browser entry mounts directly only on those public paths, while Administration receives one localized Legal section through `registerAdminSection`; authenticated API routes require the least privileged applicable role.

Published legal content is Markdown rendered by Cognis through `ui:reuse`. Each save appends an immutable version through `docs:versionStore`. The module never imports Cognis internals or a concrete database driver.

Legal editors use the host collapsible-section composer for one full-width group of document descriptors and supply its localized disclosure label so the section can render. Localized titles are plain text, while sanitized Add/Remove and Compose/Preview controls and editor content use the composer’s trusted HTML fields. The currently mounted editor determines Add or Remove state: confirming Remove closes the editor and restores Add without deleting the immutable published version. Compose and Preview use neutral host action-row buttons below the full-width, non-resizable editor, and the module uses the Cognis information-tooltip and floating dirty-tracker utilities. Adding an editor exposes a padded, non-resizable Markdown composer with message-composer-style Compose and Preview controls; the dirty tracker's Save action publishes updates through one exact API route per fixed document and reports success through the host toast. Published editors reopen with their saved Markdown after a page refresh. Discard restores published content, or closes an unsaved new editor and returns its action to Add; removing an editor requires confirmation.

## Consent and Lifecycle

The module records the exact Terms and Privacy versions accepted by each account. Registration must require explicit consent. The authenticated-session flow and a five-second foreground refresh check promptly block accounts whose recorded versions are not current; acceptance atomically records every published version and declining logs the account out. Public legal pages remain available during enforcement. Consent dialogs are mandatory and singleton, explicitly load their module styles and the core checkbox and pill styles before opening for consistent refresh and SPA rendering, expose the authenticated account-lifecycle deletion action with a plainly labeled Cancel alternative, and decline through the host logout flow. The authenticated consent integration owns idempotent right-aligned footer links within the signed-in shell. A dedicated auth-footer plugin is registered through `ctx.registerAuthFooterPlugin({ scriptUrl })`; on login and registration pages it queries the public document endpoints and contributes links only for published documents through `ui:footerLinks`. Every legal page uses the Cognis page composer. Authenticated accounts receive the full-shell composed view, while the composer suppresses its top bar, navigation, theme toggle, footer, page context, toolbar, layout persistence, and account enhancements for visitors without a login session so only the Markdown-rendered document remains. These pages use natural document scrolling and build their grouped, collapsible section navigation from rendered headings through the core `side-menu.js` reuse export. Each item supplies the heading as its `targetId`, so the core side-menu controller owns smooth, start-aligned scrolling while the module updates selection state; heading scroll margins preserve the selected heading below the fixed shell header. The consent integration remains the sole `ui:footerLinks` owner: it loads publication status even on legal routes, contributes only published documents, preserves those links across SPA page mounts, reconciles them on every route transition, forces a registry notification after a legal page mounts so a reused shell redraws its footer, and lets the core footer mark the matching route active. Each legal route applies its localized document title after authenticated shell setup so hard refreshes and SPA navigation expose the correct page context. Consent status is evaluated independently for every published Terms, Privacy, and EULA version; the persistent popup lists only unacknowledged documents as checkbox cards and submits the complete published version set. Submit remains disabled until every required checkbox is selected. The API rejects malformed or incomplete published-version sets with HTTP 400, and the client uses the host toast capability to show a localized error. For returning users, the popup link opens the normal full-size legal route with `?view=changes`; that authenticated view compares their consented hash with the latest hash through `docs:versionStore` and renders the structured result through `ui:documentDiff` so additions, removals, and changed lines are visible before consent. Plain footer links continue to open the current document. If a pre-migration historical version is absent, the API returns an explicit unavailable result and the page displays a localized explanation instead of silently hiding the comparison. Administration shows a searchable consent table only for published documents, with All, Accepted, and Outstanding filters and ten-row pagination supplied by the host `ui:pagination` capability; green and red status pills distinguish accepted and outstanding accounts, and Consented Version and Latest Version columns show the version each account accepted beside the currently published hash; accounts without recorded consent receive a localized value, and the internal unpublished sentinel is never exposed as a consented version. Legal document loading completes independently of ancillary user and consent-report requests, preventing reporting failures from presenting published editors as empty. Publishing an update immediately recalculates every displayed account status against the returned version and redraws its report. Successful consent dispatches an immediate browser event, while visible administration reports also refresh from the API every five seconds so consent recorded by other sessions appears without a page reload. Compose and Preview expose matching pressed states and a visible active-button treatment. Consent for each published document is independent; unpublished document columns use an explicit non-null sentinel. Public legal routes never display the consent popup, initialize loading and authenticated sessions before the page composer, render the version store’s Markdown field, and use a content-sized composer element so signed-in users receive a correctly sized full Cognis shell.

Scoped registrations are removed when the module is disabled. If an already-loaded browser hook observes that the module consent endpoint is temporarily unavailable during an update or restart, it logs the unavailable endpoint, yields without blocking navigation, and continues periodic retries so enforcement resumes after recovery. Back-forward cache page hides preserve active listeners and timers. Documents and consent survive disable and restart; uninstall removes them only when `deleteContent` is true. Browser resources use `cognis.uiCtx`, host feedback, navigation, API, popup, i18n, and page-entry contracts.

## Repository Quality

Root manifest, package, lockfile, and route metadata remain synchronized. Server code lives in `api/`, browser code in `ui/`, operational commands in `cli/`, localized documentation in `docs/`, release metadata in `changelog/`, and artwork in `assets/`. Tests use local capability fakes and cover routes, persistence, flows, lifecycle, localization, and packaging.
