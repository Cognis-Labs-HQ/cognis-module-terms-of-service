# 利用規約モジュール標準

この文書は Cognis 利用規約外部モジュールがサポートするアーキテクチャを定義します。

## 公開コントラクト

モジュールは公開 SPA ルート `/terms-of-service`、`/privacy-policy`、`/eula` を登録します。Browser エントリーポイントはこれらの公開パスでのみ直接 Mount され、管理画面には `registerAdminSection` を通じてローカライズされた法務セクションを1つ追加します。認証 API ルートには必要最小限のロールを要求します。

公開された法的コンテンツは Cognis が `ui:reuse` を介して描画する Markdown です。保存するたびに `docs:versionStore` を介して不変バージョンを追記します。モジュールは Cognis 内部実装や特定のデータベースドライバーをインポートしません。

法的文書エディターは、ホストの折りたたみセクション Composer を使用して文書ディスクリプターを全幅の1グループとして表示します。ローカライズされたタイトルはプレーンテキストとし、サニタイズ済みの追加/削除、作成/プレビュー操作とエディター内容には Composer の信頼済み HTML フィールドを使用します。開閉状態とは無関係に、保存済み文書バージョンの有無だけで追加または削除の状態を決定します。作成とプレビューには、全幅でサイズ変更不可のエディター下部にあるホストの中立操作行ボタンを使用し、モジュールは Cognis の情報ツールチップとフローティング変更追跡ユーティリティを使用します。エディターを追加すると、余白を備えたサイズ変更不可の Markdown 入力欄と、Messages Composer 形式の作成・プレビューボタンが表示されます。変更追跡の保存操作は固定文書ごとの正確な API ルートを通じて更新を公開し、Host のトーストで成功を通知します。公開済みエディターはページ更新後に保存済み Markdown とともに再表示されます。破棄すると公開済み内容を復元し、未保存の新規エディターの場合は閉じて操作を追加に戻します。エディターの削除には確認が必要です。

## 同意とライフサイクル

各アカウントが同意した利用条件とプライバシーの正確なバージョンを記録します。登録では明示的な同意が必須です。認証セッション Flow と5秒ごとのフォアグラウンド更新確認により、記録済みバージョンが最新でないアカウントを速やかにブロックし、同意時に公開済みの全バージョンを一括記録し、拒否時にログアウトします。強制中も公開法務ページは閲覧できます。同意ダイアログは必須かつ単一で、開く前にモジュールスタイルとコアのチェックボックスおよび Pill スタイルを明示的に読み込み、更新時と SPA ナビゲーション時の表示を統一し、認証済みアカウントライフサイクルの削除操作を提供し、拒否時はホストのログアウト Flow を実行します。同意統合が公開済み文書の右寄せ Footer リンクを冪等に一元管理します。これらの文書は公開ルートで完全な Shell を備えた構成ページとして開きます。これらのページは自然な文書スクロールを使用し、Core の再利用 Export `side-menu.js` を介して、描画された見出しからグループ化された折りたたみ可能なセクションナビゲーションを構築します。同意統合が引き続き `ui:footerLinks` の唯一の所有者となります。法務ルート上でも公開状態を読み込み、公開済み文書だけを提供し、SPA のページ Mount が切り替わってもリンクを維持して、Core Footer が該当ルートを Active として示せるようにします。各法務ルートは認証済み Shell の準備後にローカライズされた文書タイトルを適用するため、完全更新時も SPA ナビゲーション時も正しいページコンテキストが表示されます。同意状態は公開済みの利用条件、プライバシー、EULA の各バージョンごとに個別に評価され、永続ポップアップには未承認文書だけがチェックボックスカードとして表示され、公開済みの完全なバージョンセットが送信されます。必須チェックボックスをすべて選択する前に送信した場合はポップアップを開いたままにし、Host の Toast Capability でローカライズされたエラーを表示します。 管理画面では公開済み文書にのみ検索可能な同意表を表示し、すべて、承認済み、未承認のフィルターと、ホストの `ui:pagination` 機能が提供する10行単位のページングを備えます。緑と赤のステータス Pill で承認済みと未承認のアカウントを区別し、同意済みバージョン列と最新バージョン列に、各アカウントが同意したバージョンと現在公開中のハッシュを並べて表示します。同意記録がないアカウントにはローカライズされた値を表示します。更新を公開すると、返されたバージョンに対して表示中の全アカウントの状態を直ちに再計算し、レポートを再描画します。作成とプレビューには対応する押下状態と、選択中のボタンが分かる表示を設定します。公開済み文書ごとの同意は独立しており、未公開文書の列には明示的な非 Null 値を使用します。公開法務ルートでは同意ポップアップを表示せず、Page Composer より先に読み込み状態と認証セッションを初期化し、バージョンストアの Markdown フィールドを描画します。また、内容に合わせたサイズの Composer 要素を使用し、ログイン済みユーザーに適切な大きさの完全な Cognis Shell を提供します。

スコープ付き登録はモジュール無効化時に削除されます。読み込み済みの Browser Hook が更新または再起動中にモジュールの同意 Endpoint が削除されたことを検出した場合、利用不能な Endpoint を記録し、以降の同意 Request を停止して、Navigation を妨げずに処理を終了します。文書と同意は無効化や再起動後も保持され、アンインストール時は `deleteContent` が真の場合のみ削除されます。ブラウザーリソースは `cognis.uiCtx` と Host のフィードバック、ナビゲーション、API、Popup、i18n、ページエントリの各コントラクトを使用します。

## リポジトリ品質

ルートの Manifest、Package、Lockfile、Route メタデータは常に同期します。Server コードは `api/`、Browser コードは `ui/`、運用コマンドは `cli/`、ローカライズ文書は `docs/`、リリースメタデータは `changelog/`、アートワークは `assets/` に配置します。テストはローカル Capability Fake を使用し、Route、永続化、Flow、ライフサイクル、ローカライズ、Package を検証します。
