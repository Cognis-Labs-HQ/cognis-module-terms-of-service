# 利用規約モジュール標準

この文書は Cognis 利用規約外部モジュールがサポートするアーキテクチャを定義します。

## 公開コントラクト

モジュールは公開 SPA ルート `/terms-of-service`、`/privacy-policy`、`/eula` を登録します。Browser エントリーポイントはこれらの公開パスでのみ直接 Mount され、管理画面には `registerAdminSection` を通じてローカライズされた法務セクションを1つ追加します。認証 API ルートには必要最小限のロールを要求します。管理画面と同意画面が Host の内部ユーザーディレクトリ、アカウントライフサイクル Endpoint、および保護されたチェックボックス Style Contract を使用するため、Manifest は本モジュールを特権モジュールとして指定します。

公開された法的コンテンツは Cognis が `ui:reuse` を介して描画する Markdown です。保存するたびに `docs:versionStore` を介して不変バージョンを追記します。モジュールは Cognis 内部実装や特定のデータベースドライバーをインポートしません。

法的文書エディターは、ホストの折りたたみセクション Composer を使用して文書ディスクリプターを全幅の1グループとして表示し、セクションを描画できるようローカライズされた開閉ラベルを渡します。ローカライズされたタイトルはプレーンテキストとし、サニタイズ済みの追加/削除、作成/プレビュー操作とエディター内容には Composer の信頼済み HTML フィールドを使用します。現在マウントされているエディターによって追加または削除の状態を決定します。削除を確定すると、不変の公開済みバージョンを削除せずにエディターを閉じ、操作を追加に戻します。作成とプレビューには、全幅でサイズ変更不可のエディター下部にあるホストの中立操作行ボタンを使用し、モジュールは Cognis の情報ツールチップとフローティング変更追跡ユーティリティを使用します。エディターを追加すると、余白を備えたサイズ変更不可の Markdown 入力欄と、Messages Composer 形式の作成・プレビューボタンが表示されます。変更追跡の保存操作は固定文書ごとの正確な API ルートを通じて更新を公開し、Host のトーストで成功を通知します。公開済みエディターはページ更新後に保存済み Markdown とともに再表示されます。破棄すると公開済み内容を復元し、未保存の新規エディターの場合は閉じて操作を追加に戻します。エディターの削除には確認が必要です。

## 同意とライフサイクル

各アカウントが同意した利用条件とプライバシーの正確なバージョンを記録します。登録では明示的な同意が必須です。認証セッション Flow と5秒ごとのフォアグラウンド更新確認により、記録済みバージョンが最新でないアカウントを速やかにブロックし、同意時に公開済みの全バージョンを一括記録し、拒否時にログアウトします。強制中も公開法務ページは閲覧できます。同意ダイアログは必須かつ単一で、開く前にモジュールスタイルとコアのチェックボックスおよび Pill スタイルを明示的に読み込み、更新時と SPA ナビゲーション時の表示を統一し、認証済みアカウントライフサイクルの削除操作と、明確に「キャンセル」と表示された選択肢を提供し、拒否時はホストのログアウト Flow を実行します。認証済み同意統合は、ログイン済み Shell 内の冪等な右寄せ Footer リンクを管理します。専用の認証 Footer Plugin を `ctx.registerAuthFooterPlugin({ scriptUrl })` で登録し、ログインおよび登録ページでは認証済みユーザー専用の Changelog リンクを削除し、Host の公開 License リンクを維持したうえで、匿名公開 Index を一度だけ読み込み、未公開文書の Route を照会せず、公開済みと報告された文書に限ってローカライズ済み `ui:footerLinks` エントリを提供します。Plugin は各リンクの Disposer と削除した Core Descriptor を保持し、Teardown 時にモジュール所有リンクを削除して Changelog を復元します。すべての法的ページは Cognis ページ Composer を使用します。認証済みアカウントには完全な Shell を提供します。ログインセッションのない訪問者には Composer の文書フレーム、ページコンテキスト、セクションツールバーを維持しながら、アカウント依存のトップバー、ナビゲーション、テーマ切り替え、Footer、レイアウト保存、アカウント拡張を非表示にします。これらのページは自然な文書スクロールを使用し、Core の再利用 Export `side-menu.js` を介して、描画された見出しからグループ化された折りたたみ可能なセクションナビゲーションを構築します。各項目は見出しを `targetId` として渡すため、Core の Side Menu Controller が先頭位置に揃えるスムーズスクロールを担当し、モジュールは選択状態を更新します。見出しの Scroll Margin により、選択した見出しが固定 Shell Header の下に隠れません。同意統合が引き続き `ui:footerLinks` の唯一の所有者となります。法務ルート上でも公開状態を読み込み、公開済み文書だけを提供し、SPA のページ Mount が切り替わってもリンクを維持し、ルート遷移ごとに再調整し、法務ページの Mount 後に Registry 通知を発生させて再利用された Shell の Footer を再描画して、Core Footer が該当ルートを Active として示せるようにします。各法務ルートは認証済み Shell の準備後にローカライズされた文書タイトルを適用するため、完全更新時も SPA ナビゲーション時も正しいページコンテキストが表示されます。同意状態は公開済みの利用条件、プライバシー、EULA の各バージョンごとに個別に評価され、永続ポップアップには未承認文書だけがチェックボックスカードとして表示され、公開済みの完全なバージョンセットが送信されます。必須チェックボックスをすべて選択するまで送信ボタンは無効です。API は不正または不完全な公開済みバージョンセットを HTTP 400 で拒否し、クライアントは Host の Toast Capability でローカライズされたエラーを表示します。再訪ユーザーには、Popup のリンクが通常の全画面法務 Route を `?view=changes` 付きで開きます。この認証済み View は `docs:versionStore` を通じて同意済み Hash と最新 Hash を比較し、構造化された結果を `ui:documentDiff` で描画するため、同意前に追加、削除、変更された行を確認できます。通常の Footer リンクは引き続き現在の文書を開きます。移行前の履歴バージョンが存在しない場合、API は明示的な利用不可結果を返し、ページは比較を黙って隠さずローカライズされた説明を表示します。 管理画面では公開済み文書にのみ検索可能な同意表を表示し、常に1つだけが押下状態として明確に表示される、すべて、承認済み、未承認のフィルターと、ホストの `ui:pagination` 機能が提供する10行単位のページングを備えます。緑と赤のステータス Pill で承認済みと未承認のアカウントを区別し、同意済みバージョン列と最新バージョン列に、各アカウントが同意したバージョンと現在公開中のハッシュを並べて表示します。同意記録がないアカウントにはローカライズされた値を表示し、内部の未公開 Sentinel を同意済みバージョンとして公開しません。法務文書の読み込みは付随するユーザーおよび同意レポート要求とは独立して完了するため、レポートの失敗によって公開済みエディターが空として表示されることはありません。更新を公開すると、返されたバージョンに対して表示中の全アカウントの状態を直ちに再計算し、レポートを再描画します。同意が成功すると直ちに Browser Event を発生させ、表示中の管理レポートも5秒ごとに API から更新するため、別セッションで記録された同意もページを再読み込みせずに表示されます。作成とプレビューには対応する押下状態と、選択中のボタンが分かる表示を設定します。公開済み文書ごとの同意は独立しており、未公開文書の列には明示的な非 Null 値を使用します。公開法務ルートでは同意ポップアップを表示せず、Page Composer より先に読み込み状態と認証セッションを初期化し、バージョンストアの Markdown フィールドを描画します。また、内容に合わせたサイズの Composer 要素を使用し、ログイン済みユーザーに適切な大きさの完全な Cognis Shell を提供します。

スコープ付き登録はモジュール無効化時に削除されます。読み込み済みの Browser Hook が更新または再起動中にモジュールの同意 Endpoint が一時的に利用不能であることを検出した場合、Endpoint を記録し、Navigation を妨げず、定期的な再試行を続けて復旧後に同意の強制を再開します。Back-Forward Cache への Page Hide では有効な Listener と Timer を保持します。文書と同意は無効化や再起動後も保持され、アンインストール時は `deleteContent` が真の場合のみ削除されます。ブラウザーリソースは `cognis.uiCtx` と Host のフィードバック、ナビゲーション、API、Popup、i18n、ページエントリの各コントラクトを使用します。

## リポジトリ品質

ルートの Manifest、Package、Lockfile、Route メタデータは常に同期します。Server コードは `api/`、Browser コードは `ui/`、運用コマンドは `cli/`、ローカライズ文書は `docs/`、リリースメタデータは `changelog/`、アートワークは `assets/` に配置します。テストはローカル Capability Fake を使用し、Route、永続化、Flow、ライフサイクル、ローカライズ、Package を検証します。
